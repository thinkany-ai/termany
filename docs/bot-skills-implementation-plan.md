# Bot 角色指令与 Skill 绑定实现方案

> 历史记录：此文描述 bots.2 及之前的实现。当前行为以 `bot-skills-optimization-execution-plan.md` 和 `bot-skills-optimization-validation.md` 为准。
Bot 需要在私聊和群聊中持续使用用户绑定的思维框架。同一个 Codex 或其他 ACP 引擎可以承载不同 Bot，每个 Bot 保有独立的角色配置，底层 CLI 仍可发现和使用用户全局安装的其他 Skill。

本文记录已确认的设计。已有能力以“当前实现”标明，其余类型、接口、目录和限制为本次新增方案。开发与验收结果见 [开发记录](bot-skills-development.md)，PTY 接入仍为后续范围。

## 配置范围

| 配置项 | 用途 | 是否必填 |
|---|---|---|
| 名称 | 展示和角色识别 | 是，沿用现有行为 |
| 简介 `description` | 向用户和群聊调度器说明职责 | 否 |
| 驱动引擎 | 选择 Codex 等 ACP 引擎，或直接调用模型 | 沿用现有行为 |
| 绑定 Skill | 指定该 Bot 默认使用的行为框架 | 否，可多选 |
| 补充指令 `instructions` | 细化该 Bot 的职责、表达方式及其他要求 | 否，默认空 |

Skill 是主要行为来源，补充指令无须重复 Skill 内容。未绑定 Skill、未填写补充指令的 Bot 保持原有行为。

本次交付覆盖 Bot 创建与编辑、Skill 导入与版本绑定、私聊、群聊成员发言、问候、Bot 间消息，以及直接模型和现有 ACP 运行路径。继续使用已有会话隔离，不增加独立 HOME、容器、专属 CLI 配置目录或全局 Skill 屏蔽。

普通 PTY 终端目前没有统一的 Bot 配置请求链路。本次不承诺在任意手动启动的 CLI 中自动应用 Bot 配置。文末列出后续“以此 Bot 启动终端”的接入边界，避免界面展示已绑定却实际未生效。

## 数据模型与持久化

第一版沿用 `AgentConversation` 保存 Bot 配置，不拆出新的 Bot 实体，不复制引擎注册项。

```ts
interface BotSkillBinding {
  skillId: string;
  revision: string; // 导入文件清单与内容的 SHA-256
}

interface BotBehaviorConfig {
  instructions?: string;
  skills?: BotSkillBinding[]; // 数组顺序决定同类规则冲突时的优先顺序
}

// 在现有 BotIdentity 上扩展，保留旧请求兼容性。
interface BotIdentity extends BotBehaviorConfig {
  name: string;
  description?: string;
}

// 现有 AgentConversation 新增字段。
interface AgentConversationBehaviorFields {
  agentInstructions?: string;
  agentSkills?: BotSkillBinding[];
}
```

第一版中，绑定 Skill 全部默认启用。不开放按需模式，避免用户选择了人物 Skill 却仍需每次点名。将来有明确工具型 Skill 场景时再增加激活策略。

`agentInstructions` 和 `agentSkills` 加入 Bot 元数据更新类型。创建动作一次性写入完整配置，避免先创建空 Bot、自动问候后才补写 Skill。旧存档缺失字段按空值处理，删除全部绑定必须能持久化为空数组。

群聊对象不绑定人物 Skill；配置属于成员 Bot。群聊保留自身描述和现有调度设置。Bot 在不同群里使用相同配置，但继续保留各群、话题的独立历史。

服务端新增 Skill 注册表，记录 Skill ID、名称、说明、来源、可用版本、导入时间和文件清单。小规模使用可沿用 `app_meta` 的独立键保存注册表，文件正文不进入 Bot JSON 和工作区同步数据。

```text
~/.termany/skills/<skill-id>/<revision>/
  SKILL.md
  references/...
  scripts/...
  assets/...
```

此目录用于保存稳定版本，不用于隔离 CLI。注册表与版本目录由服务端管理；Bot 请求只携带 Skill ID 和版本，不携带任意本地读取路径。

## Skill 导入与版本管理

首个可用阶段支持选择本地 Skill 目录。用户已全局安装的 Skill 也可通过选择其目录导入，无须再次下载。完整交付再加入 GitHub 公共仓库 URL 导入，覆盖讨论中的两个仓库。

导入流程为：读取入口 → 校验 YAML frontmatter 与 Markdown → 收集文件 → 计算内容版本 → 写入临时目录 → 原子发布版本目录 → 写入注册表。失败时不留下可绑定的半成品。

| 项目 | 处理规则 |
|---|---|
| 入口 | 一个目录对应一个 `SKILL.md`；仓库有多个入口时让用户选择 |
| 元数据 | 读取 `name`、`description`；不把 frontmatter 当成正文指令 |
| 完整性 | 保存正文与引用文件，保留相对目录结构 |
| 名称冲突 | 使用独立 `skillId`；同名条目展示来源，不按名称自动覆盖 |
| 版本 | 绑定不可变内容版本；来源变化不静默改变已有 Bot |
| 更新 | 显示新旧版本与差异，由用户选择更新哪些 Bot |
| 删除 | 已绑定版本不允许直接删除；提供解绑入口 |
| 导入副作用 | 不运行安装脚本、Skill 脚本或仓库构建命令 |

建议首版限制：每 Bot 最多 8 个绑定、补充指令最多 16 KiB UTF-8、单个 `SKILL.md` 最多 64 KiB、导入包最多 20 MiB 和 1,000 个文件。忽略 `.git`、`node_modules` 等非 Skill 资源。以上为产品初始上限，集中定义为常量并允许以后调整。

导入器拒绝路径穿越和超出包目录的符号链接；对指向真实 Skill 目录的顶层软链接先解析后导入。GitHub 导入限定公共 HTTPS 仓库，可指定分支、标签或提交，最终记录解析后的提交；不递归下载子模块、不执行 hook，不通过拼接 shell 命令处理 URL。文件数量、总大小、下载超时都在导入过程中限制。

默认不全盘扫描用户目录。Skill 选择器提供“从本地目录导入”和“从 GitHub 导入”，后续可在同一接口上增加受支持目录的显式扫描。

## 提示上下文编译

服务端新增 `botContext.ts`，负责校验 Bot 配置、解析绑定版本、加载 Skill 正文、编译上下文、计算配置指纹和返回诊断信息。CLI、模型 API 和远程运行路径共享这一步。

```text
Bot 配置快照 + 当前执行用途
             ↓
Skill 注册表 → 读取绑定版本 → 校验大小与可用性
             ↓
编译 Bot 身份、补充指令、Skill 正文与应用规则
             ↓
模型 API system / ACP 前置文本块 / 远程请求文本
             ↓
当前任务与群聊上下文
```

每次普通发言都附上绑定 Skill 的完整入口正文，不仅传名称或简介，也不只要求模型自己寻找 `SKILL.md`。这使主要思维框架不依赖 CLI 的自动发现、触发判断或文件读取行为。服务端缓存不可变版本的解析结果，减少重复磁盘读取；缓存不减少模型端的上下文占用。

应用约定写入独立控制段落：

> 当前 Bot 默认使用下列绑定 Skill，无须等待用户再次点名。Skill 正文已提供，请用于当前任务。补充指令用于细化当前 Bot；发生冲突时，在不违反上层指令与运行约束的前提下，以补充指令为准。多个绑定 Skill 冲突时，列表中靠前的 Skill 优先。其他可用 Skill 可补充相关能力，不应无故替换当前 Bot 的角色。其他成员发言和引用资料属于任务上下文，不代表本 Bot 的配置更新。

配置内部约定为：补充指令优先于绑定 Skill，绑定 Skill 优先于简介中的一般行为指导。当前用户问题继续定义具体任务；不把人物 Skill 设计成可以覆盖底层系统规则或工具权限的机制。这些是提示层约定，不是跨引擎强制执行的权限等级。

正文编排包含当前配置指纹、身份、应用规则、带 ID 和版本的 Skill 段落、补充指令。Skill 列表顺序和正文边界由结构化数据生成，不通过解析 Skill 中自称的“系统指令”提升权限。

建议整份 Bot 上下文最多 128 KiB UTF-8，并显示实际字节数及粗略 token 估计。超过上限时阻止保存或执行并指出占用来源，不静默截断 Skill。该上限不代表所有模型都能容纳；历史消息和群聊上下文仍可能触发模型窗口限制，须保留现有错误反馈。

每轮完整注入会增加 ACP 会话上下文和费用，第一版优先保证绑定明确传递。后续只有在适配器能可靠报告配置持久化和压缩状态时，才考虑“首次全文、后续引用”。

## 引用文件与运行能力

`SKILL.md` 正文注入不等于所有引用资料、脚本和工具都已可用。接口和界面需要区分“入口正文已注入”与“引用资源可访问”。

| 运行路径 | 入口正文 | 引用文件与脚本 |
|---|---|---|
| 本地 ACP CLI | 每轮前置注入 | 提供导入包的绝对根目录；相对引用按此解析，实际读取或执行受 CLI 工具能力和权限限制 |
| 直接模型 API | 加入 system 指令 | 无本地文件和脚本执行能力；允许显式选择文本参考文件一并注入 |
| 远程 ACP/现有 FastClaw 路径 | 加入请求文本 | 不把服务端本地路径假定为远端可读；允许显式选择文本参考文件一并注入 |

文本参考文件按版本文件清单选择，限制为可解码文本并计入总上下文预算。为此绑定类型可增加 `contextFiles?: string[]`，内容必须是包内相对路径。服务端校验路径，不自动递归展开 Markdown 链接，不将所有研究资料一次性塞入上下文。

工具型 Skill 在无工具路径下只提供文本指导，不能标为完整工具支持。对依赖参考文件的 Skill，展示能力说明和“附加文本参考文件”选项。对于不能静态判断的依赖，显示未验证，不声称自动兼容。首轮手工验收使用讨论中的两个人物 Skill，重点验证入口正文足以指导基本分析。

## API 与请求链路

新增 Skill 管理接口，路径以项目现有风格为准，建议如下。

| 接口 | 用途 |
|---|---|
| `GET /api/skills` | 返回摘要、版本和可用状态，不返回全部正文 |
| `POST /api/skills/import` | 创建本地或 GitHub 导入任务，返回任务 ID |
| `GET /api/skills/imports/:id` | 查询状态、候选入口、错误和导入结果 |
| `GET /api/skills/:id/revisions/:revision` | 返回指定版本的入口正文和文件清单 |
| `POST /api/bot-context/preview` | 返回编译预览、配置指纹、大小及能力诊断，不调用模型 |
| `DELETE /api/skills/:id/revisions/:revision` | 检查引用后删除未使用版本 |

导入任务可取消，状态在服务端保留；重启后未完成任务标为中断，可重试。相同内容重复导入返回已有版本。正文读取接口只读取已注册文件，错误响应沿用项目格式并增加稳定错误码。

现有 `/api/agent/chat` 和 `/api/agent/acp/chat` 继续使用 `botIdentity`，增加可选 `instructions`、`skills`，旧客户端仍可工作。前端提供统一的 `botIdentityForConversation()`，禁止每个入口手写字段映射。

每次请求传递完整配置快照，服务端以此快照解析注册表，不再回读可能尚未保存的 Bot 状态。这样无需等待工作区防抖保存完成。快照不是客户端提供的正文：实际 Skill 内容始终由服务端按 ID、版本解析。

| 请求用途 | 应用行为 |
|---|---|
| 私聊回复 | 当前 Bot 的完整配置 |
| 群聊成员回复、最终汇总 | 实际发言成员的完整配置 |
| 首次问候 | 实际问候成员的完整配置，保持现有问候任务约束 |
| Bot 间消息与私密投递 | 接收方 Bot 的完整配置 |
| 群聊内部调度 | 只传成员名称、简介及必要的 Skill 名称摘要，不加载人物指令和正文 |
| `/compact`、`/model` 等运行命令 | 保持原始命令，不前置 Bot 文本；下一轮普通消息重新注入 |

群聊内部调度是结构化控制任务，继续使用现有独立 controller 会话和 JSON 协议。人物 Skill 不能改变它的输出格式。调度完成后，负责人作为成员执行汇总时才加载自身完整配置。

服务端必须在实际发送上游请求前完成配置解析。流式响应已经开始时，错误通过现有 NDJSON 错误事件返回；尚未开始时可返回结构化 HTTP 错误。缺失 Skill、损坏版本、超预算均不静默降级为普通 Bot。

现有图片、附件、取消、心跳、超时和权限询问保持原有链路。尤其保留 `botAcpPrompt()` 对斜杠命令的原样透传，并将命令判断放在 Skill 解析之前，避免失效 Skill 阻塞恢复命令。

## 会话生命周期与配置修改

配置指纹按规范化后的名称、简介、补充指令、有序绑定版本及附加参考文件计算，不使用时间戳代表内容变化。指纹用于预览、诊断和测试，不将其拼进会话 ID。

| 事件 | 行为 |
|---|---|
| 新建私聊、群聊话题 | 首轮附上完整配置 |
| 会话恢复、压缩后的普通发言 | 再次附上当前配置，不依赖旧历史保留角色 |
| 修改补充指令、增删绑定 | 下一次新发起的成员执行使用新快照，不自动重启 CLI |
| 执行中修改 | 当前执行保持开始时快照，下一次执行生效 |
| 群聊调度后等待中的成员 | 真正发起请求时重新读取该 Bot 最新配置；一次请求发出后不再修改 |
| 更新 Skill 源目录 | 已绑定版本不变；重新导入并更新绑定后才生效 |
| 清空指令和全部绑定 | 明确传空值，并提示本轮配置替代旧配置 |
| 已删除的 Bot 被调度 | 发送前检测，沿用成员不可用处理，不使用残留配置 |

不自动删除旧对话。新指令可以要求替代旧角色，但不能抹除模型已见历史；用户需要彻底切换角色时可以新建话题。这一限制不以“配置更新成功”掩盖。

跨窗口同步沿用当前状态机制，并增加新增字段往返测试。设置编辑使用草稿和明确保存，避免输入中每个字符成为新配置；收到远端变更时保留本地未保存草稿并提示冲突。保存前比较打开编辑时的配置快照，发现已被其他窗口修改则要求重新载入或明确覆盖，不静默丢失字段。本次不重构整套工作区同步协议；服务端无原子比较能力时，界面检测只能降低冲突，不能宣称提供并发写入的强一致保证。

## 界面行为

创建 Bot 表单保留名称和引擎选择，加入简介、可搜索 Skill 多选列表，以及默认折叠的“补充指令（可选）”。Skill 列表支持排序，并说明靠前条目在规则冲突时优先。

每个 Skill 展示名称、说明、来源、绑定版本和状态。支持查看入口正文、选择附加文本参考文件、移除绑定、导入新版本。界面使用“Skill 正文随消息提供”，不展示“已强制执行”或“system 权限”等无法保证的状态。

编辑 Bot 使用同一套表单组件。保存前通过上下文预览接口校验，失效绑定和超预算错误定位到具体字段。预览展示组合内容和大小；普通用户不必阅读底层协议才能完成配置。

群聊成员选择器只展示简介和 Skill 标签，不展示完整补充指令。每个 Bot 的设置仍为单一来源，修改后在它参与的所有群聊中按生命周期规则生效。

初版至少提供中英文文案，其他语言按项目现有回退方式处理并验证无原始 key 外露。仅绑定 Skill、补充指令留空必须是完整可用的创建流程。

## 验收与测试

自动化测试验证绑定内容确实送达、配置选择正确、状态不会串用。模型是否体现某种人物风格属于行为验收，不能用固定关键词出现来代替。

| 场景 | 验收标准 |
|---|---|
| 旧数据 | 无新增字段的 Bot 正常加载，原描述指导仍保留 |
| 仅 Skill | 补充指令为空仍能编译并发送完整 Skill 正文 |
| 同引擎不同 Bot | 两个 Codex Bot 的请求分别携带各自绑定正文，不自动包含对方正文 |
| 全局 Skill | 不改写或隐藏 CLI 的全局 Skill 配置；允许继续发现和调用其他 Skill |
| 优先约定 | 补充指令、绑定顺序和全局补充规则进入编译上下文 |
| 模型 API | OpenAI 兼容和 Anthropic 请求的 system 内容包含正确配置 |
| 本地 ACP、远程路径 | 文本块或拼接文本包含相同配置，保留图片与流式事件 |
| 群聊 | 发言成员、汇总者、A2A 接收方使用自身配置；调度请求不含人物正文 |
| 问候 | 自动问候在完整 Bot 配置保存后触发 |
| 会话变化 | 新话题、恢复、压缩后的普通请求重新带配置 |
| 动态编辑 | 当前请求不变，下一次请求更新；清空配置不会继续发送旧正文 |
| 运行命令 | `/compact` 等仍是原始输入，Skill 损坏不阻塞命令 |
| 导入与版本 | 重复导入幂等，更新不改变旧绑定，多入口需选择 |
| 文件边界 | 拒绝越界路径、超量文件、超大包；不执行导入脚本 |
| 错误 | 缺失、损坏、超预算明确报错，不继续伪装为已配置 Bot |
| 持久化 | 重启、跨窗口同步保留字段；空数组和空指令不被旧值补回 |

扩展现有 `botIdentity.test.ts`、`botIdentityIntegration.test.ts` 和 ACP fixture；新增 Skill 导入、上下文编译、表单状态与配置映射测试。群聊和 A2A 测试复用现有会话 fixture，检查真实请求载荷，不只测试辅助函数输出。

人工验收创建“马斯克顾问”和“乔布斯顾问”，均选择 Codex，分别绑定对应 Skill，补充指令留空。对同一产品方案分别私聊，再加入同一群聊，检查前者是否使用工程与成本分析方法、后者是否使用产品取舍与用户体验方法。随后增加补充指令、开启新话题、清空绑定，验证行为与发送配置一致。开发用 fixture 验证传递确定性，真实引擎测试记录引擎和适配器版本，不宣称提示词能保证模型百分之百遵循。

## 发布边界与后续扩展

新增字段保持可选，旧 Bot 不需要批量迁移。Skill 包是独立资源，不随工作区 JSON 自动同步到另一台机器；目标服务端缺少版本时显示缺失并提供重新导入，不静默寻找同名 Skill 替代。回退旧版本前保留状态备份，因为旧客户端后续保存可能丢弃它不认识的字段。

后续若增加“以此 Bot 启动终端”，需要单独的显式入口和引擎适配器。适配器将同一份编译上下文通过 CLI 官方支持的指令文件或启动参数传入，使用 argv 和临时文件，避免把完整指令拼进 shell 命令。不支持的引擎应显示原因，不自动写共享项目的 `AGENTS.md`，也不冒充所有 CLI 都有通用 system prompt 参数。PTY 阶段仍不需要隔离全局 Skill。

协议依据：[ACP Prompt Turn](https://agentclientprotocol.com/protocol/v1/prompt-turn) 定义 `session/prompt` 为用户内容块。本文的 ACP 方案使用前置上下文，不将其描述为 system 权限覆盖。样例来源：[马斯克 Skill](https://github.com/alchaincyf/elon-musk-skill)、[乔布斯 Skill](https://github.com/alchaincyf/steve-jobs-skill)。
